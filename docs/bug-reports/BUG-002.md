# BUG-002: Dashboard scrolls sideways on mobile after the first transaction

| Field | Value |
|---|---|
| **Status** | Fixed, regression test added (`TC-UI-11`) |
| **Severity** | Minor: layout broken, no data impact |
| **Priority** | Medium: most MFS users are on phones |
| **Module** | Dashboard UI, Recent transactions table |
| **Found by** | Exploratory check of a mobile screenshot (Pixel 7 viewport, 412 px wide) |

## Summary
Once the transaction history has a row, the table is wider than a phone screen. The whole page then scrolls horizontally, cards are cut off on the right, and the pink header no longer spans the full width.

## Steps to reproduce
1. Open the app in a 412 px wide viewport (Chrome DevTools → Pixel 7).
2. Log in as 01711111111 / 1234.
3. Send 500 BDT to 01822222222 with PIN 1234.
4. Swipe left on the page.

## Expected result
The page fits the screen. Only the table scrolls inside its own card.

## Actual result
The whole page is wider than the screen (`scrollWidth > clientWidth`).

## Root cause
The cards are CSS grid items. Grid items default to `min-width: auto`, so they cannot shrink below the width of their content, and the table pushed the card (and the page) wider. Wrapping the table in `overflow-x: auto` alone did not help because of this.

## Fix
- Table wrapped in a `.table-wrap` container with `overflow-x: auto`.
- `min-width: 0` on `.card` so grid items can shrink.

## Regression test
`TC-UI-11` sends money, then asserts `document.documentElement.scrollWidth - clientWidth <= 0`.
It runs on both desktop and mobile. It was confirmed to **fail** before the fix and pass after it.
