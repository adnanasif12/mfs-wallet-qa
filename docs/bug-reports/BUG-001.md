# BUG-001: Send Money rejects the maximum allowed amount (25,000 BDT)

| Field | Value |
|---|---|
| **Status** | Open (seeded defect, kept to demonstrate boundary testing) |
| **Severity** | Major: a valid, common high-value transaction is blocked |
| **Priority** | High |
| **Module** | Send Money API (`POST /api/send-money`) |
| **Found by** | Automated BVA test `TC-SM-02 BVA amount 25000 (exact maximum)` |
| **Environment** | Local, Node 22, test DB seed data |

## Summary
Per BR-07 the Send Money limit is 10 to 25,000 BDT **inclusive**. Sending exactly 25,000 BDT is rejected with "Maximum amount is 25000 BDT".

## Preconditions
- Customer 01711111111 is logged in.
- Balance is at least 25,005 BDT (agent cash-in of 25,000 first).

## Steps to reproduce
1. `POST /api/login` with `{"phone":"01711111111","pin":"1234"}` and copy the token.
2. As the agent, `POST /api/cash-in` with `{"customerPhone":"01711111111","amount":25000,"pin":"1111"}`.
3. As the customer, `POST /api/send-money` with `{"receiverPhone":"01822222222","amount":25000,"pin":"1234"}`.

## Expected result
`201 Created`. 25,000 BDT is sent with a 5 BDT fee.

## Actual result
```json
HTTP 400
{ "error": "AMOUNT_ABOVE_MAX", "message": "Maximum amount is 25000 BDT" }
```
24,999.99 is accepted and 25,000.01 is rejected correctly, so only the exact boundary is wrong.

## Root cause
Off-by-one comparison in `app/server.js`:
```js
if (amount >= r.max)   // wrong
if (amount >  r.max)   // correct
```

## How the suite tracks it
The test is marked `test.fail()` with an `issue` annotation, so CI stays green while the bug is open.
When the fix is merged, that test will pass, Playwright will report it as "unexpectedly passed", and the `test.fail()` line must be removed. This stops a known bug from being forgotten.
